# K/D/A Scoreboard 구현 인계서

## 목적

Minecraft Bedrock 폭파전 애드온에 전용 아이템을 들고 있는 동안 표시되는 경기 점수판 오버레이를 구현한다. 기준 이미지는 아래 로컬 첨부 파일이다.

`C:\Users\tifj7\.codex\codex-remote-attachments\01a0c695-2a3e-7393-9719-3ea0b0500550\42F802EA-AAD5-4429-A1F7-6FEFD15DB287\1-사진-1.jpg`

이미지에서 가져올 핵심 시각 언어는 다음과 같다.

- 화면 중앙을 넓게 덮는 반투명 검정 패널
- 왼쪽 방어팀은 파랑, 오른쪽 공격팀은 주황
- 중앙 상단에 양 팀의 현재 라운드 점수
- 양쪽 패널에 최대 5명의 플레이어 행
- 현재 사용자의 행은 밝은 반투명 배경과 밝은 글자로 강조
- 사망한 플레이어 행은 어둡게 표시
- 오버레이 뒤로 월드와 기존 HUD가 계속 보임

## 확정된 제품 사양

### 호출 방식과 아이템

- 팀 참가가 확정되면 화면 기준 핫바 4번(API 인덱스 `3`)에 전용 아이템을 지급한다.
- 새 커스텀 아이템 식별자는 `fps:scoreboard`, 표시 이름은 한국어 `점수판`, 영어 `Scoreboard`로 한다.
- 아이콘은 짙은 회색 보드에 파랑·주황 두 팀 줄이 들어간 전용 아이콘을 사용한다.
- 아이템은 최대 스택 1이며 슬롯에 고정한다. 이동, 투척, 소모가 불가능해야 한다.
- 아이템을 사용하는 것이 아니라 **선택해 손에 들고 있는 동안** 오버레이를 표시한다.
- 다른 슬롯을 선택하면 애니메이션 없이 즉시 숨긴다.
- 살아 있거나 사망 후 관전 중이어도 점수판 아이템과 기능을 유지한다.
- 팀 미참가 로비 플레이어에게는 지급하지 않는다.
- 경기 종료 화면이 끝나 완전히 새 경기로 초기화될 때 회수한다.

### 레이아웃과 가시성

- 점수판은 JSON UI HUD의 최상단 레이어에 둔다.
- 점수판 표시 중에도 기존 상단 HUD, 무기·탄약 HUD, 킬 로그, 게임 이벤트 배너를 숨기지 않는다.
- 왼쪽 패널은 항상 현재 방어 역할(CT), 오른쪽은 현재 공격 역할(T)이다.
- 하프타임 역할 교대 시 플레이어가 반대 패널로 이동하되 누적 수치는 유지한다.
- 팀별 최대 5명을 표시한다.
- 각 행에는 고정 팀 아이콘을 사용한다. 실제 플레이어 스킨 얼굴은 사용하지 않는다.
- 표시 언어는 리소스팩 언어에 따른다. 한국어와 영어 키를 모두 추가한다.
- K/D/A와 숫자는 언어와 무관하게 공통으로 표시한다.
- 각 클라이언트에서 본인 행만 강조한다.

### 열 구성과 정보 공개

- 기본 열 순서는 `# | 이름 | K | D | A`이다.
- 현재 사용자의 **아군 패널에만** `자금` 열을 추가한다.
- 상대 패널에는 자금 값뿐 아니라 자금 열 자체가 존재하지 않는다.
- 상대 자금은 클라이언트 wire 데이터에도 포함하지 않는 편이 안전하다.
- 팀 안의 정렬 순서는 다음과 같다.
  1. K 내림차순
  2. A 내림차순
  3. D 오름차순
  4. 경기 참가 순서
- `#` 값은 정렬 결과에 따른 팀별 1~5 순위다.

### 경기 누적 통계

- K/D/A는 한 경기 전체 누적이다.
- 하프타임에는 초기화하지 않는다.
- 완전히 새 경기가 시작될 때 0으로 초기화한다.
- 적 플레이어를 직접 처치했을 때만 K를 1 올린다.
- 자살, 낙사, 환경사, 팀킬은 K로 인정하지 않는다.
- 원인과 관계없이 실제로 사망하면 D를 1 올린다.

### 어시스트

- 죽은 적에게 이번 생명 동안 유효 피해를 준 아군 가운데, 직접 킬을 하지 않은 플레이어만 후보가 된다.
- 후보 중 누적 피해가 가장 높은 **한 명**에게만 A를 1 올린다.
- 최고 누적 피해가 동률이면 그 피해 대상에게 **처음 피해를 준 플레이어**가 이긴다.
- 자해, 팀킬, 환경 피해는 기여에서 제외한다.
- 피해 기록은 피해 대상이 사망하거나 라운드가 종료될 때 삭제한다.
- 피해량 최저 임계치는 없다. 유효 피해가 0보다 크면 후보가 될 수 있다.

### 연결 해제

- 플레이어가 연결을 끊으면 점수판 행, 누적 K/D/A, 해당 플레이어가 공격자 또는 피해자로 들어간 어시스트 기여 기록을 즉시 완전 삭제한다.
- 이는 soft delete가 아닌 hard delete다.
- 같은 플레이어가 다시 참가하면 K/D/A는 `0/0/0`부터 시작한다.
- 핵심 경기 상태가 연결 해제 처리를 위해 플레이어 레코드를 보존해야 한다면, 점수판 전용 통계 저장소에서 hard delete 의미를 보장하고 재참가 때 기존 통계를 복원하지 않는다.

## 현재 프로젝트에서 확인한 구조

- 프로젝트는 TypeScript 원본 `src/`를 `behavior_pack/scripts/`로 빌드한다. 생성된 JavaScript를 직접 수정하지 않는다.
- `package.json`의 현재 버전은 `1.1.24`, `@minecraft/server`는 `2.3.0`이다.
- 검증 명령은 `npm.cmd run check`, 패키징은 `npm.cmd run package`이다.
- 고정 핫바 계약은 `src/inventory.ts`와 `docs/OFFICIAL_BEDROCK_REQUIREMENTS.md`에 있다.
  - 0 주무기, 1 보조무기, 2 칼, 3~6 전술 장비 예약, 7 C4, 8 상점
  - 이번 기능은 전술 장비 예약의 첫 칸인 API 슬롯 `3`을 사용한다.
- 커스텀 아이템 정의는 `behavior_pack/items/`, 아이템 아틀라스는 `resource_pack/textures/item_texture.json`, 번역은 `resource_pack/texts/*.lang`에 있다.
- `src/game.ts`가 spawn/leave/death/hurt 이벤트, 인벤토리 동기화, HUD 발행을 통합한다.
- 현재 들고 있는 아이템은 `player.selectedSlotIndex`와 `heldItemId()`를 통해 확인할 수 있다.
- 기존 상단 HUD는 Title 채널의 202바이트 고정 프레임이며 `src/hud.ts`, `resource_pack/ui/hud_elements/gamemodes/bombdefusal.json`, `docs/HUD_PROTOCOL.md`에 계약이 있다.
- 개인 HUD는 ActionBar의 20바이트 `FCAB` 프레임이다. 기존 프로토콜과 생성 파일 계약을 깨지 말아야 한다.
- HUD 루트 삽입은 `resource_pack/ui/hud_screen.json`, 정의 목록은 `resource_pack/ui/_ui_defs.json`에 있다.
- 기존 팀 고정 아이콘은 다음 자산을 재사용할 수 있다.
  - `resource_pack/textures/ui/team_defender_player.png`
  - `resource_pack/textures/ui/team_attacker_player.png`
- 역할 교대 계산은 `RoundLifecycle.currentRole()`/`roleForSquad()`가 이미 담당한다.
- 킬 귀속은 `src/game.ts::onDeath()`에서 `combat.resolveDeath()` 결과를 받은 후 처리한다.
- 피해 이벤트는 `MinecraftCombatAdapter.hurtEvent()`가 `victimId`, `attackerId`, `damage`, 원인 정보를 `CombatExecution.handleHurt()`에 전달한다.
- `PlayerMatchState`에는 현재 K/D/A 필드가 없다. 지속 방식은 명시적으로 설계해야 한다.
- 현재 `playerLeave`는 핵심 `PlayerMatchState`를 제거하지 않고 `connected=false`로 둔다. 점수판 통계 hard delete를 이 동작과 분리하는 것이 안전하다.

## 권장 구현 방향

아래는 확정 요구사항이 아니라, 기존 계약을 덜 흔드는 권장 방향이다. 더 나은 방식이 있으면 테스트로 근거를 남기고 변경해도 된다.

1. `src/scoreboard/` 같은 독립 모듈에 깊은 경계를 둔다.
   - 경기 통계 원장(K/D/A, 참가 순서)
   - 피해 기여 원장(피해자별 공격자 누적 피해와 최초 타격 순서)
   - 정렬과 뷰어별 스냅샷 생성
   - 고정 길이 wire 인코딩/디코딩
2. 통계는 매치 상태와 함께 저장할지 런타임 전용으로 둘지 결정한다.
   - 현재 `recover()`는 진행 중 경기를 로비로 되돌리므로 런타임 전용도 가능하다.
   - 저장한다면 `state.ts`에서 이전 저장 데이터와의 하위 호환 sanitize가 필요하다.
3. 피해 기록은 팀 판정과 실제 유효 피해를 검증한 뒤 기록한다.
   - `entityHurt`의 보고 피해량과 `CombatExecution`의 보정 피해가 다를 수 있으므로 중복 또는 과소 집계 여부를 테스트한다.
   - 팀 피해는 `CombatExecution.handleHurt()`에서 복구될 수 있으므로 단순 이벤트 수신만으로 기록하지 않는다.
4. `onDeath()`에서 먼저 유효 킬러/팀 관계를 확정한 뒤 K, D, A를 원자적으로 반영하고 피해자 기여 원장을 비운다.
5. 라운드 종료 효과 처리 지점에서 전체 피해 기여 원장을 비운다. 누적 K/D/A는 유지한다.
6. `onLeave()`에서 해당 플레이어의 통계와 모든 기여 관계를 hard delete한다.
7. 전용 아이템을 `FIXED_HOTBAR_LAYOUT.tactical[0]`에 배치하고 기존 sanitize/sync가 지우지 않도록 핫바 계약을 확장한다.
8. 기존 Title과 ActionBar 채널을 덮어써서는 안 된다. 점수판용 데이터는 기존 상단 HUD 정보와 함께 보낼 수 있는 별도/확장 프레임으로 설계하되, 뷰어별 아군 자금 공개 정책을 서버에서 보장한다.
9. JSON UI는 새 영구 HUD 정의 파일로 분리하고 `_ui_defs.json`과 `hud_screen.json`에 등록한다. 삽입 순서와 충분히 높은 `layer`로 최상단을 보장한다.
10. 화면 종횡비와 GUI scale이 달라도 중앙 패널이 잘리지 않도록 퍼센트 기반 크기와 최대 폭을 사용한다.

## 구현 시 주의할 함정

- `syncWeaponsToFixedHotbar()`와 `sanitizeFixedHotbarInventory()`는 현재 전술 슬롯 3~6을 적극적으로 비운다. 아이템 지급만 추가하면 다음 동기화 틱에 사라질 수 있다.
- 사망 처리의 `clearMatchItems()`가 점수판 아이템까지 제거할 수 있다. 사망 관전자에게도 유지해야 하므로 match item 정리 정책을 함께 수정해야 한다.
- 로비용 나침반/시계, 8번 C4, 9번 상점 아이템의 기존 동작을 훼손하면 안 된다.
- 기존 Title wire는 UTF-8 바이트 오프셋을 사용하며 202바이트를 강제한다. 이름을 추가 인코딩할 때 문자 수와 바이트 수를 혼동하지 않는다.
- 플레이어별 아군 패널이 달라지므로 하나의 공용 스냅샷만으로 자금 공개 정책을 구현하면 상대 자금이 노출될 수 있다.
- 하프타임에는 역할만 바뀌며 통계 원장의 플레이어 ID와 참가 순서는 유지해야 한다.
- `ROUND_END`에서도 사망 이벤트가 처리될 수 있는 현재 규칙을 존중한다.
- 저장 상태 스키마를 바꾸면 구버전 월드 로드에 대한 sanitize 테스트를 추가한다.
- 저장소 전체가 현재 Git 기준으로 untracked로 보인다. 관련 없는 파일을 삭제하거나 초기화하지 않는다.

## 최소 테스트 범위

### 단위 테스트

- 새 통계 원장은 K/D/A를 정확히 반영한다.
- 자살·환경사·팀킬은 K를 올리지 않고 D만 올린다.
- 어시스트는 최고 피해자 한 명만 받는다.
- 최고 피해 동률이면 최초 타격자가 받는다.
- 직접 킬러는 어시스트 후보에서 제외된다.
- 피해자 사망, 라운드 종료, 연결 해제 시 기여 원장이 정확히 정리된다.
- 연결 해제 후 재참가 통계가 0부터 시작한다.
- 정렬은 K desc, A desc, D asc, 참가 순서다.
- 역할 교대 후 패널이 바뀌어도 통계는 유지된다.
- 뷰어별 스냅샷에서 아군 자금만 포함된다.
- UTF-8 이름을 포함한 wire 길이/오프셋이 안정적이다.

### 통합/계약 테스트

- 4번 슬롯에 아이템이 생기고 인벤토리 sanitize/무기 sync/사망 후에도 유지된다.
- 팀 미참가 로비 플레이어에게는 지급되지 않는다.
- 아이템 선택 시만 오버레이 visible 조건이 참이 된다.
- 다른 슬롯 선택 시 즉시 숨겨진다.
- 기존 HUD, FCAB, 킬 로그, 배너 정의가 유지된다.
- 새 UI 정의가 `_ui_defs.json` 및 `hud_screen.json`에 등록되고 최상단 layer를 사용한다.
- BP/RP manifest 버전과 패키지 버전이 기존 프로젝트 규칙에 맞게 함께 증가한다.
- 패키지 안에 새 BP 아이템, RP UI, 아이콘, 번역, 빌드된 스크립트가 포함된다.

### 수동 확인

- 최소 1대1과 최대 5대5에서 패널 정렬 및 빈 행 확인
- 한국어/영어 전환 확인
- 16:9, 좁은 화면, 모바일 GUI scale에서 잘림 확인
- 생존/사망/관전/하프타임/경기 종료 구간에서 아이템 및 표시 확인
- 기존 상단 HUD, 무기 HUD, 킬 로그, 배너가 점수판 아래에서 계속 렌더링되는지 확인

## 완료 조건

- `npm.cmd run check`가 통과한다.
- `npm.cmd run package`가 통과한다.
- 생성된 `.mcaddon`에 필요한 모든 파일이 포함된다.
- 첨부 이미지의 좌우 팀 패널, 색상, 반투명도, 중앙 점수, 행 강조가 육안상 재현된다.
- 위의 확정 사양과 테스트 항목 중 미구현 또는 임의 변경된 항목이 없다.
